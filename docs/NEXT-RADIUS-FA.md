# تحویل بعدی: RADIUS دسترسی کارشناسان

این فایل برنامهٔ ماژول بعدی است؛ سرویس RADIUS در نسخه 1.7.0-rc.2 نصب یا فعال نشده است. پس از تست و تأیید خروجی فعلی توسط کاربر، توسعه از همین سورس ادامه می‌یابد.

## محدوده ماژول

| تب Radius | رفتار موردنیاز |
|---|---|
| Access Devices | افزودن IP تکی یا رنج تجهیزات، نوع Cisco/MikroTik، Secret اختصاصی و فعال/غیرفعال |
| Profiles | نام پروفایل مانند Support، نگاشت Cisco privilege و MikroTik group مطابق مدل/نسخه |
| Users | کاربر کارشناس، انتخاب پروفایل، وضعیت و تغییر رمز؛ جدا از حساب مدیر پنل |
| Reports | ورود موفق/ردشده، کاربر، NAS، زمان و Accounting در حد اطلاعات واقعی تجهیز |
| Configuration | نمونه کانفیگ وابسته به مدل و نسخه، راه آزمایش و بازگشت؛ بدون تغییر خودکار تجهیزات |

## اتصال به برنامه فعلی

کد در modules/radius قرار می‌گیرد؛ رابط در همان پنل و منوی Radius باز می‌شود و از ورود و مجوزهای پنل استفاده می‌کند. backend از قرارداد createModule(ctx)/API1 استفاده خواهد کرد. FreeRADIUS سرویس همراه با compose.module.yml و نصب/ارتقای مختص ماژول خواهد داشت. جدول‌ها و مهاجرت‌های جدید اختصاصی‌اند؛ schema.sql پایه بازنویسی نمی‌شود. در صورت نیاز به تکمیل runner مهاجرت ماژول‌ها، یک Patch کوچک و نسخه‌دار برای Core همراه خروجی داده می‌شود.

تحویل شامل ZIP ماژول، وابستگی دقیق به نسخه Core، نصب، حذف بدون پاک‌کردن داده، بکاپ، تست درخواست RADIUS و گزارش نتیجه خواهد بود. ادعای استقلال کامل صرفاً با جداکردن پوشه مطرح نمی‌شود؛ نصب و ارتقای ماژول باید با Core تست شود.

## تست و ادامه

ابتدا تست محلی قبول/رد، فعال/غیرفعال، نگاشت پروفایل و گزارش؛ سپس یک Cisco و یک MikroTik آزمایشی، با مدل و نسخه اعلام‌شده توسط کاربر. رمز تجهیزات در گفتگو لازم نیست. ثبت همه دستورات CLI بدون پشتیبانی مدل/پروتکل وعده داده نمی‌شود.

پس از این ماژول: Network Map در سه خروجی نقشه/پورت‌ها، مسیر MAC و بکاپ؛ سپس MAC Access و 802.1X. خواندن MAC از سوئیچ در همه مراحل فقط با درخواست دستی کاربر است. جست‌وجو روی Snapshot ذخیره‌شده و همراه زمان آخرین خواندن خواهد بود.
