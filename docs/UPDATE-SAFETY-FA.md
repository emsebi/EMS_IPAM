# محدوده حفاظت هنگام ارتقا

نصب‌کننده قبل از جایگزینی کد SQL backup فشرده با pg_dump داخل کانتینر دیتابیس می‌گیرد و gzip را بررسی می‌کند. volume و .env در ارتقای عادی حذف/بازنویسی نمی‌شوند. ارتقای Core از --remove-orphans استفاده نمی‌کند، دیتابیس را عمداً pull نمی‌کند و پوشه افزونه‌های اضافی را نگه می‌دارد.

پس از fail شدن build یا health، کد قبلی برمی‌گردد. این **rollback دیتابیس نیست**؛ مهاجرت داده فقط با فایل‌های برنامه برنمی‌گردد. پیش از ارتقا روی داده مهم، کپی VM/دیتابیس و تمرین restore لازم است. بکاپ قبل از update به فرمت .sql.gz است؛ بکاپ درون پنل .tar.gz حاوی database.dump و metadata.env است. این دو فرمت یکی نیستند.

ارتقای سرتاسری روی Docker در محیط ساخت اجرا نشده است. چک‌لیست و تست VM در START-HERE-FA.md قرار دارند. بازگشت برنامه 1.6.1 بعد از تغییر Typeها می‌تواند Seed قدیمی را فعال کند؛ کد و دیتابیس باید از یک نقطه هماهنگ بازیابی شوند.
